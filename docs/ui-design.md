# UI / UX 设计决定

**状态：`IMPLEMENTED`（已实现于原型）——`PROPOSED`（提议）部分未验证。**
**记录日期：2026-10-17**

本文记录界面骨架与关键交互的取舍，以及**为什么**这么选。视觉实现基于 Flare + Material Design 3。

## 1. 骨架：左侧导航 + 主内容区

三个功能**同级**放在侧边栏，不再是一页到底的纵向卡片流：

```
┌──────────┬──────────────────────────────────┐
│ 顶栏      │ 调色板切换                        │
├──────────┼──────────────────────────────────┤
│ Bin 修改  │                                  │
│ 资产浏览  │           主内容区                │
│ 字节码查看│                                  │
│          │                                  │
│ 原型阶段  │                                  │
└──────────┴──────────────────────────────────┘
```

**为什么**：

- 工具型应用的肌肉记忆（对标 VS Code / AssetRegistryTool），用户能直接点到功能，不用滚页面。
- 三者是**并列能力**而非先后步骤——字节码查看和 Bin 修改没有依赖关系，做成向导会误导。
- 后续加面板只动侧边栏，不改骨架。

**实现**：`FlareLayout` + `FlareLayoutDrawer(Variant=Permanent, Width=15rem)` + `FlareLayoutContent`。

## 2. 空状态：全屏拖放区

未载入文件时，主内容区就是一个**占满高度的拖放区**，而不是「空列表 + 载入按钮」。

**为什么**：

- 打开就知道第一步干什么，不需要读说明。
- 拖入后直接进入工作区，没有中间态。

**实现**：`.solstice-drop` 占 `calc(100dvh - 64px)`，内部放 `InputFile`；`wwwroot/js/dropzone.js` 把拖入的文件转交给 input 并触发 `change`。**没有 JS 时仍可点击选择**，不是纯拖放。

## 3. 新增卡牌：模态对话框

**为什么**：

- 一次只加一张，模态能强制「完成或取消」，不会留下半填状态。
- 表单字段少（国家 / 系列 / 类型 / 名字），对话框放得下。
- 不打断列表上下文（将来有列表时，关掉对话框还在原位）。

**实现**：`FlareDialog` + `ChildContent` + `ActionsContent`，正文实时预览 `AssetName` / `PackagePath` / `ObjectPath`。

> 注意：`FlareDialog` 只接受 `IconContent` / `ChildContent` / `ActionsContent` 三个顶层子内容，裸写标记会报 `RZ9996`。

## 4. 写回确认：只显示总数

点「下一步」后弹确认框，显示 **新增 / 修改 / 删除** 三个数字，不逐行 diff。

**为什么**：

- 首期操作是「加一张卡」，改动量为 1，逐行 diff 是杀鸡用牛刀。
- 2000+ 条目的 diff 界面本身很重，收益低。
- 真正的安全网在读回校验，不在视觉预览。

**代价**：批量操作时会不够看。届时再补三组可展开清单。

## 5. 主题：MD3 五套调色板

Flare 的 MD3 基线主题自带 **Violet / Blue / Green / Teal / Orange** 五套，顶栏直接切换，不需要自定义品牌色。

**为什么**：开箱即用，后续要换品牌色只改 `Program.cs` 一行（`Palette.FromColors`）。主题 / 调色板 / 明暗是三个独立轴，明暗跟随系统。

## 8. UKAPI 上层（节点/字节码编辑）的形态

2026-10-17 决定。这四项直接对应 UKAPI 的数据模型，不是视觉偏好。

### 8.1 主体是平铺的表达式列表，控制流不随列表走

字节码里表达式就是一个**线性数组**，跳转靠 `EX_Jump` / `EX_JumpIfNot` 的偏移指回去。
所以主视图做成**平铺列表**（一行一个表达式，顺序 = 数组顺序），
**控制流单独表达**（在列表上画出跳转连线/标记），而不是把 `if` 渲染成嵌套块。

**为什么**：嵌套树是把线性数组「重新解释」成结构，一旦遇到不规则跳转就会失真；
平铺列表与数据模型 1:1，不需要做有损转换，也不会出现「UI 上看着对、写回去不对」。

**代价**：不如蓝图编辑器直观，长函数需要靠跳转标记来读。

### 8.2 两个页面：查看/编辑 vs 新建/生成

对应 ADR 0002 的双路径：

| 页面 | 能做什么 | 对应能力 |
|---|---|---|
| 查看 / 编辑 | 看既有函数，只改参数与常量 | 最小编辑路径 |
| 新建 / 生成 | 从 `FunctionDescription` 生成新函数 | UKAPI 单向生成 |

不放在同一个画布里切换模式——两条路径的写回逻辑完全不同，混在一起容易误操作。

### 8.3 从引脚拖出时弹出候选函数

`functions.json`（1,416 个 kards 函数 / 2,653 个参数）的主要用途就是这个：
从某个引脚往外拖时，按**当前上下文**（引脚类型、所在类、是否 exec）过滤并排序候选。

不做常驻侧栏函数库作为主入口——函数太多，浏览不如按上下文推荐。

### 8.4 选中节点 → 右侧属性面板

参数与常量在右侧面板改，不用弹窗、不内联。理由：画布不被遮挡，
可以连续改多个节点，与主流节点编辑器一致。
