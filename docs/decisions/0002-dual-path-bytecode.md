# ADR 0002：字节码能力采用双路径

- 状态：Accepted（已接受）
- 日期：2026-10-17
- 关联：[ADR 0001](0001-one-way-ukapi.md)

## 背景

ADR 0001 规定 UKAPI 是**单向生成器**，不承诺把既有字节码还原成高层模型。

但在 KARDS 的 Mod 场景里，最高频的需求是**改既有函数里的参数与常量值**（改伤害数值、改调用的目标函数、改判定条件）。这类需求无法用单向生成器覆盖——既有函数没有对应的高层 `FunctionDescription`，也就无从「重新生成」。

与此同时，完整就地编辑（插入/删除表达式、重排控制流）会立刻撞上跳转偏移重算，这正是 ADR 0001 与 `docs/bytecode-generation.md` 反复警告的高风险区。

## 决定

字节码能力拆成**两条互不依赖的路径**：

1. **生成路径（UKAPI）**：面向**新建**函数，从 `FunctionDescription` 单向生成受支持的 Kismet 结构。完全遵循 ADR 0001。
2. **最小编辑路径**：面向**既有**函数，只允许修改**参数与常量值**。不插入、不删除、不移动表达式。

两条路径共享只读解析能力，但写回逻辑分开实现、分开测试。

## 后果

**正面**

- 覆盖真实需求，同时把风险限制在可控范围。
- 最小编辑路径**不需要重建 CFG，也不需要重算跳转偏移**——只要表达式数量与长度不变，偏移全部有效。
- 与 ADR 0001 不冲突：生成仍然是单向的，编辑不伪装成生成。

**代价**

- 两套代码、两套测试、两套诊断。
- 「只改参数」需要精确定位目标表达式与目标字段，依赖成熟的只读解析能力。
- 一旦将来要支持插入/删除表达式，就必须重算偏移，届时需要新的 ADR，本条不构成对该能力的任何承诺。

## 待验证

- **修改参数/常量是否真的不改变序列化长度**：数值类型通常定长，但字符串、Name、结构体数组会变长，一旦变长，后续跳转偏移就会失效。这条必须在实现前用真实样本验证。
- KARDS 是否存在运行时缓存或资源哈希校验，导致改完不生效。
